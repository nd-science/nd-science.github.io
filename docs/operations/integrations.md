# План внешних интеграций

Хостинг по плану: GitHub для кода и Markdown-контента; Cloudflare Pages для preview и production каждого приложения отдельно. Preview закрывается Cloudflare Access и `noindex`. Заявки хранятся только в защищённом почтовом ящике: отдельная база не создаётся, письма удаляются через один год.

## Формы (Cloudflare Pages Functions)

1. Обработчик `packages/forms` размещается как Pages Function каждого приложения (`functions/api/enquiry.js`).
2. Настроить Turnstile (site key в `PUBLIC_TURNSTILE_SITE_KEY`, secret в `TURNSTILE_SECRET_KEY`).
3. Настроить Resend (`RESEND_API_KEY`, `FORM_FROM_EMAIL`, `FORM_TO_EMAIL`); отдельные адреса назначения для Wellness и Science.
4. Включить приём только после legal review: `PUBLIC_FORMS_ENABLED=true` и `LEGAL_REVIEW_APPROVED=true`. До этого показывается заглушка.
5. Автоответ RU/EN сообщает срок ответа, отсутствие подтверждённой записи и запрет присылать конфиденциальные материалы.
6. Проверить валидацию, honeypot, rate limit, Turnstile, ошибку Resend, повторную отправку и отсутствие параметров форм в аналитике.

## Google Calendar

1. Подтвердить аккаунт и календарь Наталии.
2. Настроить доступные окна и буферы между встречами.
3. Проверить, какие персональные данные собирает форма.
4. Приватная ссылка календаря отправляется вручную после подтверждённой оплаты.

## Поисковые системы

После выбора доменов и публичной сборки подтвердить владение в Google Search Console, Bing Webmaster Tools и Яндекс Вебмастере. Инструкции и verification-файлы хранить без секретов.

## Аналитика

Cloudflare Web Analytics без cookies. Параметры форм, контакты и чувствительные данные в аналитику не передавать. Маркетинговые трекеры не подключать по умолчанию.

## Оплата

Не подключать до письменного решения по статусу фрилансера в Сербии, банку, валютам, возвратам, чекам и налоговой отчётности. Текущий сценарий — ручные счёт и ссылка ЮKassa по картежу записи; встроенные checkout-интеграции не используются.
