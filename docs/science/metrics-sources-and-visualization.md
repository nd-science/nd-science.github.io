## 4. Способы подключения

### Вариант A — снимок при сборке (рекомендуется)

Скрипт на этапе сборки забирает данные из открытых API, кладёт их в JSON в репозиторий, страница рендерит статический HTML.

```js
// scripts/fetch-metrics.mjs — запускается вручную или в CI
const orcid = "0000-0003-0816-2103";
const authors = await fetch(
  `https://api.openalex.org/authors?filter=orcid:${orcid}&mailto=site@example.org`
).then((r) => r.json());

const a = authors.results[0];
const byYear = await fetch(
  `https://api.openalex.org/works?filter=author.id:${a.id.split("/").pop()}&group_by=publication_year`
).then((r) => r.json());

await writeFile(
  "apps/science/src/data/metrics.json",
  JSON.stringify({
    checkedAt: new Date().toISOString().slice(0, 10),
    openalex: {
      id: a.id,
      hIndex: a.summary_stats.h_index,
      i10: a.summary_stats.i10_index,
      works: a.works_count,
      citations: a.cited_by_count,
    },
    citationsByYear: byYear.group_by.map((g) => ({ year: Number(g.key), count: g.count })),
  }, null, 2)
);
```

Плюсы: нулевой клиентский JS, нет внешних трекеров, значения фиксируются с датой, ключи остаются на машине сборки. Минусы: данные устаревают между сборками — это честно решается подписью «по данным OpenAlex на 29.10.2026».

### Вариант B — запрос из браузера

OpenAlex и Crossref отдают CORS-заголовки, поэтому метрики можно тянуть прямо со страницы. Плюс: значения всегда свежие. Минусы: сайт зависит от чужого API и лимита запросов, посетитель раскрывает запрос третьей стороне, при ошибке нужен запасной контент. Для сайта в статусе `draft` это лишний риск.

### Вариант C — официальные бейджи

| Бейдж | Что показывает | Встраивание |
| --- | --- | --- |
| Altmetric donut | внимание в СМИ и соцсетях | `<script src="https://d1bxh8uas1mnw7.cloudfront.net/assets/embed.js">` + `data-doi`; при нуле упоминаний смысла нет |
| Dimensions badge | цитаты и Field Citation Ratio | скрипт `badge.dimensions.ai` по DOI |
| PlumX | цитирования, использование, захваты | скрипт `plu.mx`; для её DOI данных нет |
| ORCID iD | идентификатор, не метрика | статичная SVG-иконка со ссылкой на профиль |

Плюсы: узнаваемость, данные обновляет провайдер. Минусы: сторонние скрипты (приватность, скорость, отказ в РФ-сетях), неподконтрольный дизайн, значения без даты проверки.

### Вариант D — ручной ввод

Для Scopus, Web of Science и РИНЦ другого способа сейчас нет: значение и ссылку вносит редактор, дата проверки хранится рядом. Именно этот вариант соответствует текущим правилам проекта — метрика без базы, ссылки и даты не публикуется.

## 5. Схема данных

```ts
// packages/profile/src/metrics.ts
export type Metric = {
  database: "openalex" | "scopus" | "wos" | "rsci" | "crossref";
  label: string;           // как называть в интерфейсе
  value: number;
  url: string;             // ссылка на профиль или работу
  checkedAt: string;       // ISO-дата проверки
  note?: string;           // например: "без самоцитирования"
};

export type CitationYear = { year: number; count: number };
```

Правила: значение относится только к одной базе; агрегаты и «средний h-index» не считаются; каждая запись имеет URL и дату; при отсутствии данных блок не рендерится, а не показывает ноль.

## 6. Визуализация

Что работает на проверяемом профиле:

1. **Таблица-источник истины.** Колонки: показатель, база, значение, дата проверки, ссылка. Таблица остаётся доступной и без графики.
2. **Столбики публикаций по годам.** Данные OpenAlex уже отдают `group_by=publication_year`: 2007–2026, максимум 6 работ в 2018 году. Это показывает реальную траекторию, а не украшение.
3. **Плашки идентификаторов.** ORCID, Scopus Author ID, ResearcherID — как ссылки-чипы, без чисел.
4. **Разделение по базам.** Отдельные карточки «Scopus: h = 2, 7 документов», «OpenAlex: h = 3, 29 работ» с подписью, почему числа разные.

Чего не делать: круговых диаграмм с «общим индексом», графиков роста h-index без истории, счётчиков цитирований с чужих профилей, анимаций, обещающих рост показателей.

Технически график — обычный SVG, собранный на сервере:

```astro
---
// apps/science/src/components/CitationsByYear.astro
const { data, checkedAt } = Astro.props;
const max = Math.max(...data.map((d) => d.count), 1);
const w = 24, gap = 8, h = 96;
---
<figure>
  <svg viewBox={`0 0 ${data.length * (w + gap)} ${h + 24}`} role="img"
       aria-label={`Публикации по годам, ${data.length} лет, максимум ${max}`}>
    {data.map((d, i) => (
      <g>
        <rect x={i * (w + gap)} y={h - (d.count / max) * h} width={w}
              height={(d.count / max) * h} />
        <text x={i * (w + gap) + w / 2} y={h + 16} text-anchor="middle">{d.year}</text>
      </g>
    ))}
  </svg>
  <figcaption>Публикации по годам. Источник: OpenAlex, проверено {checkedAt}.</figcaption>
</figure>
```

Доступность: один смысловой текст в `aria-label`, подпись с источником и датой, значения дублируются в таблице, цвет не единственный носитель смысла, анимации отключаются через `prefers-reduced-motion`.
